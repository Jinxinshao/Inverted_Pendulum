# 08 常见问题与故障排查

## 安装与启动

| 现象 | 原因 | 处理 |
|---|---|---|
| `找不到 pendulum_lab.exe` | 可执行文件名是 `pendulum-lab`（连字符） | 用 `python -m pendulum_lab gui` 或 `pendulum-lab gui` |
| `No module named pendulum_lab` | 没在工程目录执行 `pip install -e .`，或装到了另一个 Python/conda 环境 | 激活正确环境后重装；`where python` 检查 |
| 安装日志里 `~uggingface-hub` 警告 | 环境里其他包的残留 | 与本软件无关，可忽略 |
| GUI 中文乱码或方框 | matplotlib 缺中文字体 | Windows 自带微软雅黑，一般正常；曲线标签用英文不受影响 |

## 串口

| 现象 | 原因 | 处理 |
|---|---|---|
| `could not open port` / 拒绝访问 | 端口被 VOFA+、XCOM 或原厂上位机占用 | 关闭它们；一个串口同时只能被一个程序打开 |
| 驱动器无应答 / timeout | 12 V 未开（总线电压 4.47 V 就是这个原因）；波特率不对；**协议选错**（custom/modbus）；地址不对 | 用原厂上位机确认协议类型；`diagnose --motor COM11 --protocol modbus` 两种都试 |
| 驱动器回 E6 / Modbus 异常 3 | 数据超出范围，如速度 < 0.1 rpm | 软件对零速会自动改用 0.1 rpm；其他情况查看日志中的帧 |
| Modbus 下电压显示 −207.96 V、就绪检查乱报 | 旧版代码读回复时去错了补齐字节 | 已修正（补齐字节在末尾，09 章 9.1 节）；更新代码 |
| 传感器速率低于 200 Hz | ADC 板固件输出太慢 | 见 05 章第 1 步的固件建议，或增大 `loop.Ts` |

## 驱动器状态

| 现象 | 原因 | 处理 |
|---|---|---|
| 发速度指令电机不动 | 未使能；处于刹车锁存；工作模式不是通信速度模式；堵转保护 | “一键准备”；或依次“设为通信速度模式 → 清除电机状态 → 使能” |
| 刹车后无法再运动 | FC 刹车会锁存 | 清除电机状态（FB），再使能（FA 00）。开始闭环时软件会自动执行 |
| `PREFLIGHT FAILED: PD42S1 not ready: 电机未使能` | 旧版把 0x2F 的使能标志读反了（实测 0 = 使能）；另外 `drivertest` 结束时会让电机失能 | 已修正：改读 0x31，开始闭环时自动“清除状态 → 使能 → 零速”。更新代码即可，和限位开关无关 |
| 影子模式一直是 WAIT_ARM | 杆没有被扶到直立 ±3° 并保持 1 s | 正常现象；扶到直立附近即进入 ACTIVE |
| 就绪检查提示“指令回响已关闭” | 自定义协议下回响被关 | “打开指令回响” |
| 电机发热 | 长时间刹车或使能保持 | 不用时失能 |

## 闭环行为

| 现象 | 最可能的原因 | 验证 / 处理 |
|---|---|---|
| 松手瞬间小车猛冲到一端 | **符号错**（角度或 +x 定义） | 影子模式：杆向 +x 倾时 a 必须为正；重做 05 章第 2、4 步 |
| 小车缓慢漂向一侧后停住或撞限位 | 零点偏差 | 看日志 `bias_hat`；确认零偏估计已开；重新标定直立 |
| 高频抖动、噪音大 | 延迟被低估；皮带间隙；滤波微分截止频率太高 | `motor-step` 重测延迟；张紧皮带；用卡尔曼滤波 |
| 约 0.3 Hz 的慢摆动 | 转轴库仑摩擦（电位器力矩） | 实测 $\gamma$；参见 03 章第 7 节 |
| 越来越大的振荡 | 延迟超过裕度 | 降低增益（增大 $r$）；启用延迟感知设计；检查 USB 转串口的 latency timer |
| “predicted stop” 安全停车 | 小车速度太大，按刹车减速度会越过软限位 | 正常保护；降低 $q_\theta$ 或增大软限位（在导轨允许范围内） |
| “angle sensor stale” | 传感器数据中断 | 检查 USB 线；关闭其他占用 CPU 的程序 |
| 日志中 `dt` 偶有 > 10 ms | Windows 调度 | 使用 Python ≥ 3.11；关闭杀毒实时扫描；GUI 已采用独立进程 |

## 辨识

| 现象 | 原因 | 处理 |
|---|---|---|
| 旧版 `identify` 给出 $\omega_0\approx11.8$（约 2 倍） | 滑片跨越死区时的毛刺被当成转折点（02 章 2.10 节） | 已修正：新方法 A 先剔除毛刺；请更新代码后重新分析 |
| “only N turning points found” | 摆幅太小、录制太短 | 从 90° 松手，录 60 s |
| A 与 B 相差 > 0.3 %，或两侧 $\omega_0$ 不一致 | 松手时推了一下、桌面振动、中途碰到杆，或采样率低 | 重录，松手后不要碰桌子 |
| CSV 开头有上千行时间相同 | 旧版录制程序在等待回车时积压了串口数据 | 已修正（每段开始前清空缓冲区）；分析程序会自动跳过这些行 |
| 录制程序显示“最大偏离 181°” | 旧版把死区毛刺当成有效角度 | 已修正（分两侧给出摆幅） |
| 在线辨识“不可信” | 没有激励、有人推杆、尚未收敛 | 打开激励，勿触碰，运行 ≥ 30 s |
