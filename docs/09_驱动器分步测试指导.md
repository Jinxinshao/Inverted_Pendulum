# 09 驱动器分步测试指导（`drivertest`）

这一章回答三个只能在实物上确认的问题。它们决定闭环时软件能否可靠地停车：

| 问题 | 为什么重要 | 测试方式 |
|---|---|---|
| **Q1** 发 0 rpm，电机能否真正停住？ | 软件的每一次“停车”都是先把速度斜坡降到 0 rpm。若 0 rpm 不被接受或停不住，停车就不可靠 | 慢速走 1 cm，发 0 rpm，用编码器看是否停住（自动判定） |
| **Q2** Modbus 协议里，奇数长度的数据补齐字节放在哪？ | 放错会让所有读数错位一个字节，比如电压读成乱码、使能状态读反 | **已由您的截图回答**，程序只做只读复核（见下文） |
| **Q3** 速度模式下，左右限位开关能否让电机停下？ | 决定限位开关能不能当作最后一道保护 | 小车在导轨中间慢速移动，**由您用手指按下限位开关**，程序记录电机是否停下 |

全程电机最快 20 rpm，按 40 mm/圈估算约 13 mm/s。每次运动不超过 1 s（Q1）或 4 s（Q3），小车始终在导轨中部，**不会开到导轨两端**。

## 9.1 您的截图已经回答了 Q2

在原厂上位机“设备系统”页，读系统参数时的日志帧是：

```
[发] 01 04 00 31 00 14 A1 CA                       读 0x31，20 个寄存器 = 40 字节
[收] 01 04 28 | 41 C3 4F F4 | FF F8 | 40 74 F3 AA | 3F DD 76 5E | 40 82 9E BC | 00 00 |
              |  24.41 V    | -8 mA |  3.827 mWb  |  1.730 Ω    |  4.082 mH   | 0 rpm |
              00 00 96 B8 | 00 00 96 CA | FF FF FF EE | 00 00 00 00 | 00 | 00 | 00 | 00 | CE A6
              目标 38584  | 实时 38602  |  误差 -18   | 累计脉冲 0  |使能|到位|堵转|补齐| CRC
```

0x31 的数据有 39 字节，Modbus 按寄存器（2 字节）传输，所以回了 40 字节。**补的 0x00 在最后**，其余每一项都和界面上显示的数值逐一对上。

结论与软件修正：

- **读回复（04H）补在末尾**。原来的代码按“补在开头”去掉了第一个字节，这会让 Modbus 下的系统参数整体错位：电压会读成 −207.96 V，就绪检查也会误报。**已修正**，并把这两帧原样写进了自动测试（`tests/test_pd42s1_protocol.py::test_odd_length_read_pad_is_trailing`），解码结果必须与截图完全一致。
- **1 字节的读取**（如 0x2F 使能标志）：补齐字节为 0，所以无论补在前还是后，两个字节按位“或”就是数值。软件已这样处理，两种约定都正确。
- **写单个寄存器（06H）**：原厂日志 `01 06 00 FA 00 01` 表示“失能”，即 1 字节数值放在寄存器的**低字节**。这一条早已由日志确认。
- 本软件实际用到的多寄存器写（10H）只有 F1 速度指令，6 字节为偶数，不涉及补齐。

测试程序第 0 步还会再做一次只读复核：读出电压、实时位置等，请您对照原厂上位机确认。

## 9.2 截图里还有两件要注意的事

1. **工作模式当前是“通信力矩模式”**。本软件用 F1 速度指令，需要“**通信速度模式**”。测试程序第 1 步会询问您，并按“失能 → 设为速度模式 → 读回确认 → 清除状态 → 使能 → 零速”的顺序切换，过程中电机不会转。您也可以在原厂上位机里把“工作模式”改为通信速度模式，点“设置驱动参数”，再点“保存设备参数”。
2. **总线电压 24.41 V**。之前的截图是 12 V 系统。24 V 在手册允许范围（12–32 V）内，电机高速转矩会更好。软件的检查门限是 ≥ 11 V，不需要改动。

## 9.3 先演练（不接硬件，5 分钟）

建议先在不接驱动器的情况下完整走一遍，熟悉每一步会问什么：

```bat
python -m pendulum_lab drivertest --sim
```

程序连接的是按手册编写的驱动器模拟器。模拟器初始为力矩模式，和您的实物一样；它没有限位开关，所以第 3 步应当显示“没停”。

## 9.4 实物测试前的准备（逐条做到）

1. **关闭原厂上位机**（同一个串口只能被一个程序打开）。VOFA+ 只占用 COM12，可以不关。
2. 摆杆**自然下垂**，不需要扶。
3. 小车**推到导轨正中间**（离两端都 > 20 cm）。
4. 皮带、线缆周围没有手和杂物。
5. 一只手放在**电源开关**上。这是最终急停，任何时候觉得不对就直接断电。
6. 程序运行中：
   - 任意提示处输入 `q` 回车：退出，程序发 0 rpm 并失能电机；
   - 任何时候按 **Ctrl+C**：同上，立即停止并失能。

## 9.5 运行

```bat
python -m pendulum_lab drivertest --motor COM11 --protocol modbus
```

驱动器当前是 Modbus 协议，地址 1，波特率 115200，程序默认就是这些值。若要把第 4 步皮带标定的结果直接存进配置文件，加上 `--write config\physical_config.json`。

只做其中几步可以用 `--steps`，例如只做只读检查和模式切换：`--steps 0,1`。

### 第 0 步　只读检查（电机不会动）

屏幕显示固件版本、总线电压、实时位置、工作模式、速度环 PID、限位开关功能开或关等。

**您要做的**：打开原厂上位机的截图对照，电压约 24.4 V，实时位置数值接近。一致就输入 `y`。

注意：程序运行时原厂上位机必须关着，所以只能对照截图，不能两个程序同时开。

### 第 1 步　工作模式

显示“当前为 通信力矩模式(2)……现在切换？”，输入 `y`。

- 程序读回确认模式为“通信速度模式(1)”。
- 接着问“是否保存设备参数”，建议 `y`，下次上电仍是速度模式。
- 最后清除状态、使能，并发 0 rpm。此时电机处于“使能 + 零速”，用手推小车应当推不动，这是正常的。

### 第 2 步　问题 1：0 rpm 能否停住

按回车后：

1. 小车以 20 rpm 正转 0.8 s，约走 1 cm。
2. 程序发 0 rpm，观察 1.2 s。
3. 程序问“刚才正转(+)时小车往哪边走”，看一眼后输入 `L`（左）或 `R`（右）。
4. 小车反转 0.8 s 走回来，再发 0 rpm 观察。

**屏幕上会显示**（数值为模拟器演练结果，实物会不同）：

```
正转(+): 走了 +10.3 mm；0 rpm 被接受；约 23 ms 内停住；0.4 s 后漂移 0 计数（0.000 mm）→ 通过
```

判定标准：

- 0 rpm 被接受（没有返回 Modbus 异常 3）；
- 发 0 rpm 0.4 s 以后，编码器变化 ≤ 40 计数（约 0.03 mm）；
- 读回的实时转速为 0。

如果驱动器拒绝 0 rpm，程序会改发 0.1 rpm（手册下限，约 0.07 mm/s，可视为停止），并在结论里写明。

### 第 3 步　问题 3：限位开关

共 4 次，每次程序先说明，例如：

```
-- 正转(+)（向右走），按【小车正驶向的那一侧=右侧】限位开关 --
按回车后小车以 10 rpm 慢速移动 4 s；看到它开始动后，用手指按住右侧限位开关约 1 s 再松开
```

**您要做的**：按回车，看到小车开始慢慢移动（约 7 mm/s）后，**用手指按下它正驶向的那一侧的限位开关**，保持约 1 秒后松开。4 秒后小车自动停下。

- 小车只走约 2.7 cm，离开关还远，**不会真的撞上**。“撞限位”由您的手指模拟。
- 结束时程序问“你按下开关时，电机停了吗？”，按您看到的回答 `y` 或 `n`。
- 程序另外会用编码器自动检测有没有“指令在动、电机却停住”的时间段，并与您的回答互相核对。

4 次分别是：两个方向 ×（按驶向一侧 / 按背离一侧）。这样可以同时回答：

- 限位开关能不能让电机停；
- 是否区分方向（按背离一侧时正常情况下不应停）；
- 松开后是自动恢复运动，还是锁存（驱动器变为失能或堵转，需要“清除状态 + 使能”）。如果锁存，程序会询问是否恢复，回答 `y` 即可。

**如果 4 次都“没停”，并且驱动器的“限位开关功能”是关的**：截图里回零参数显示“左右限位 关”，这种情况是预期内的。程序会问要不要**临时**打开限位功能再测一次。回答 `y` 后，程序打开功能（不保存），重做两次“驶向一侧”，然后**自动恢复为关**。

### 第 4 步　皮带标定（可选，但闭环前必须做）

需要一把钢尺和一小段胶带。按提示：

1. 在小车侧面对着导轨贴胶带标记；
2. 小车以 20 rpm 走 1.5 s；
3. 用钢尺量出移动距离，输入毫米数；
4. 用 GUI 驱动器页的点动把小车移回标记，按回车记录中点。

结果是“每圈 mm”（GT2 20 齿理论值为 40 mm）。

### 结束

程序问“让电机失能？”，建议 `y`。之后可以用手推动小车。然后打印结论，例如：

```
问题 1（0 rpm）：驱动器接受 0 rpm；两个方向都能停住，软件直接发 0 rpm 即可。
问题 2（Modbus 补齐）：读回复 末尾补 0x00……你确认与官方软件一致；单字节读取一致。
问题 3（限位开关）：驱动器限位功能关；4 次中有 0 次开关让电机停下。
日志：data/driver_selftest_20260927_153000.txt
收发帧：data/driver_selftest_20260927_153000_frames.csv
```

**请把 `data\` 下这两个文件发给我**。第一个是全部提示、回答和测量结果，第二个是每一帧收发的十六进制数据和延迟。有了它们，我可以确认驱动器的实际行为，并把结论写进软件的安全逻辑。

## 9.6 结果如何影响后续设置

| 结果 | 软件和操作上的对应 |
|---|---|
| Q1 通过 | 保持现状：停车时软件把速度斜坡降到 0 rpm。 |
| Q1 被拒绝、改发 0.1 rpm | 软件已自动处理；停车后小车每秒爬行约 0.07 mm，可忽略。 |
| Q1 停不住 | **不要闭环**，把日志发给我。 |
| Q3 限位能停，且只拦驶向一侧 | 可在 GUI 驱动器页打开“左右限位”并保存，作为硬件层面的最后保护。 |
| Q3 限位能停，但会锁存 | 同上；撞限位后需要“清除状态 + 使能”，这与手册中刹车后的恢复流程相同。 |
| Q3 限位不起作用 | 只能依靠三层保护：①软件软限位 `safety.x_soft`（按“预测停车位置”提前刹车）；②驱动器堵转保护（您的设置为开，2500 mA）；③电源开关。闭环前务必完成皮带标定和中点设置，软限位才有意义。 |

## 9.7 常见疑问

- **会不会一开始电机就猛转？** 不会。第 0 步只读；第 1 步切换模式时电机先失能，使能后立即发 0 rpm。所有运动都是 10–20 rpm。
- **小车撞到端头怎么办？** 每次运动最多 1 cm（Q1）或 2.7 cm（Q3），从导轨中间出发不可能撞到。万一发生，直接断电。
- **程序卡住不动？** 按 Ctrl+C，程序会先发 0 rpm 再失能。如果串口已经断开，就直接断电。
- **原厂上位机和本程序能同时开吗？** 不能。同一个 COM11 只能有一个程序使用。先关原厂上位机再运行本程序，结束后再打开原厂软件查看状态。
