# 05 实物调试流程（从只读诊断到首次闭环）

每一步都有**通过标准**，不通过就不要进入下一步。标定结果保存在 `config/physical_config.json`（从 `physical_config.example.json` 复制，或由 GUI 自动生成）。以下命令都在工程根目录执行，`COM11`/`COM12` 换成设备管理器中的实际端口。**同一个串口同时只能被一个程序打开**：运行本软件前请关闭原厂上位机、VOFA+、XCOM。

## 第 0 步 安全硬件（必须）

1. 电源开关（2026-09-27 截图为 24 V 供电）放在操作者手边，作为急停。可串一个蘑菇头急停开关。
2. 导轨两端的机械挡块要牢固，小车撞上时不会脱轨。
3. 限位开关在速度模式下是否有效，用 `drivertest` 第 3 步验证（[09 章](09_驱动器分步测试指导.md)）：小车在导轨中间低速移动，用手指按开关，**不要让小车真的开到限位处**。2026-09-27 实测（限位功能为“关”）：**不会停**。所以保护依靠软件软限位（±25 cm）、驱动器堵转保护和电源开关。
4. 皮带张紧到用手指按压几乎不变形。间隙 2 mm 时角度抖动由 0.03° 增至 0.3–0.4°（[基准结果](benchmark_results.md)）。
5. 线缆不能被小车拖拽。

## 第 1 步 角度传感器数据流（只读）

```bat
python -m pendulum_lab diagnose --sensor COM12 --seconds 10
```

通过标准：

- 解析正常（`ADC=1966, 1584 mV` 格式已支持）；
- **采样率 ≥ 200 Hz**（控制周期 5 ms）；若为 100–200 Hz，把 `loop.Ts` 改大并重新设计（仿真可先试 `--Ts 0.01`，结果见 [基准结果](benchmark_results.md)）；
- 间隔 p99 < 10 ms；
- 静止时噪声 ≤ 1 LSB（0.085°）。

XCOM 截图中接收计数 R:135691 字节，但不知道时长，无法推算速率，以本步实测为准。若速率不够，建议 ADC 板固件：

- 用定时器触发 ADC 采样，每 2 ms 一次（500 Hz），每次 16 点过采样取平均；
- 输出 `ADC=%u,T=%lu\r\n`，`T` 为 MCU 微秒计数。软件已支持该格式，可区分真实采样抖动与 USB 抖动；
- USB CDC 的“波特率”是虚设的，不限制速率。

## 第 2 步 角度标定

两种方式任选：GUI“参数辨识”页的“角度标定助手”，或

```bat
python -m pendulum_lab calibrate-angle --sensor COM12 --write config\physical_config.json
```

1. 下垂静止：分别从左、右轻敲后各记录一次，取平均，消除 ±0.4° 的摩擦带；
2. 直立：用铅垂线或水平仪对准，扶稳后记录；
3. 向 **+x 侧**（电机正转时小车前进的方向，第 4 步确定后再复核）倾斜约 10°，记录，程序据此判定符号。

通过标准：斜率在 670–685 LSB/rad 之间（摆动辨识 678.1，手册 680.1）；符号为 ±1。

注意：本装置的下垂读数（约 4091）被电位器端点截断，真正的最低点在死区内（02 章 2.10 节），不能作 180° 参考。程序检测到这种情况时会自动改用摆动辨识得到的斜率。所以本步最重要的是：**直立读数（铅垂线对准）和符号**。

## 第 3 步 自由摆动辨识（建议完成，决定模型精度）

**录制**（二选一）：

- 独立程序，只需 pyserial，可以发给老师分析：
  ```bat
  python scripts\record_potentiometer.py --port COM12 --seconds 60
  ```
- GUI“参数辨识”页 → “开始录制”。

操作：程序先录 3 s 静止下垂，然后提示“把杆拉到约 90° 松手”。**松手时不要推**，之后不要碰桌子。

**分析**：

```bat
python -m pendulum_lab identify --csv swing_xxx.csv --write config\physical_config.json
```

或在 GUI 中点“采用方法 A”。输出包括（原理见 02 章 2.10 节、03 章第 8 节）：

- 数据质量：采样率、剔除的死区样本和毛刺、过死区次数、释放角；
- 传感器自标定：最低点读数、斜率、死区位置与宽度、外推的直立读数；
- 方法 A（转折点 + 能量平衡，**推荐**）：$\omega_0$，左右两侧分别的 $\omega_0$，7 种阻尼模型的 AIC 表；
- 方法 B（状态变量滤波 + 最小二乘）：独立验证 $\omega_0$。

通过标准：

- A 与 B 的 $\omega_0$ 相差 < 0.3 %，两侧的 $\omega_0$ 相差 < 0.05 %；
- $\omega_0$ 在 5.4–5.7 rad/s 之间（2026-09-27 实测 5.5147）；
- 外推的直立读数与第 2 步的铅垂线读数相差 < 15 LSB（约 1.3°）。

**2026-09-27 第一次录制已完成并通过**，结果已设为默认值。换摆杆或配重后需要重录。

## 第 4 步 驱动器与小车标定（小车会移动几厘米）

**先运行驱动器分步测试**（[09 章](09_驱动器分步测试指导.md)，约 10 分钟）：

```bat
python -m pendulum_lab drivertest --sim                              :: 先演练，不接硬件
python -m pendulum_lab drivertest --motor COM11 --protocol modbus --write config\physical_config.json
```

它依次完成四件事：

1. 只读复核 Modbus 解码；
2. 把工作模式从“通信力矩模式”切换为“通信速度模式”；
3. 回答“0 rpm 能否停住”和“限位开关在速度模式下是否有效”；
4. 做皮带标定。

生成的两个日志文件请发给老师。下面 1–5 项是 GUI 里的等价操作。

1. GUI“驱动器”页：选串口、波特率、**协议**（与原厂上位机设置一致），点“连接”；或命令 `python -m pendulum_lab driver info --motor COM11 --protocol modbus`。
2. “一键准备”：通信速度模式 + 回响 + 清除状态 + 使能 + 零速。然后点“就绪检查”，应显示“就绪”。
3. 点动：按住“正转 ▶”，小车移动；松开即停，最长 3 s。**小车正转时移动的方向定义为 +x**，在导轨上贴标签。
4. 皮带标定向导：①记录起点 → ②正转运行 → ③量距离、计算 → ④点动回中心并保存。结果为每圈行程 $\ell$、中心计数、编码器方向。命令行等价：`python -m pendulum_lab calibrate-cart --motor COM11 --write config\physical_config.json`。
5. 复核第 2 步的符号：杆向 +x 侧倾斜，θ 应为正（GUI 影子模式里看 θ 曲线）。

通过标准：$\ell$ 与带轮规格相符（GT2-20 齿为 40 mm）；重复标定偏差 < 1 %。

## 第 5 步 执行器动态与延迟

```bat
python -m pendulum_lab motor-step --motor COM11 --config config\physical_config.json
python -m pendulum_lab probe --motor COM11 --rate-hz 100 --count 1000 --csv data\probe_100hz.csv
```

`motor-step` 给出命令延迟 $L$、速度环滞后 $\tau$、速度增益（应≈1）。把 $L$ 加上第 1 步测得的传感器延迟，写入 `loop.latency_estimate`；把 $\tau$ 写入 `loop.actuator_tau`。然后运行

```bat
python -m pendulum_lab design --config config\physical_config.json --latency <L> --tau <tau>
```

查看各算法的延迟裕度。通过标准：`probe` 在 100 Hz 下错误率为 0；延迟裕度 > 实测总延迟的 2 倍。

## 第 6 步 影子模式（电机不动，绝对安全）

GUI“实物运行”→ 模式“影子模式”→ 开始；或 `python -m pendulum_lab run --mode shadow --config config\physical_config.json`。

用手把杆扶到直立附近（±3° 保持 1 s 进入 ACTIVE；影子模式不等松手），然后缓慢向 +x 倾斜。杆一直下垂时状态会一直停在 WAIT_ARM，这是正常的（2026-09-27 的影子模式日志就是这种情况：13.7 s 全部为 WAIT_ARM；同时它表明实时性很好：周期 p99 = 5.00 ms，传感器数据龄期 p99 = 5.9 ms）。**加速度指令 a 应为正**，即控制器会让小车向 +x 加速去“接住”杆。通过标准：符号正确；日志 `report` 中周期 p99 < 6 ms。

## 第 7 步 首次闭环

1. 配置参数：
   - `safety.x_soft = 0.25`（默认值）：以**开始时小车所在位置**为中心，左右各 25 cm。70 cm 导轨两边各留约 10 cm 刹车余量。软件按“预测停车位置”提前刹车：0.5 m/s 时刹车距离约 4 cm，加上 30 ms 延迟约 1.5 cm。
   - `actuator.a_max = 4`，`safety.max_runtime = 30`。
   - 算法先用 LQR（延迟感知）。
2. **小车推到导轨正中间**（软限位以此为中心，由 `hardware.cart.center_mode = "start"` 决定；若改为 `"fixed"`，则使用皮带标定时记录的中点）。一人扶杆，一人手放在电源开关上。
3. GUI“实物运行”→ 闭环 → 开始，确认对话框。软件依次：
   - 执行手册规定的“清除电机状态 → 使能 → 零速”；
   - 做就绪检查（通信速度模式、电压、未堵转、已使能）；
   - 把当前位置记为中点。

   工作模式不会自动切换：必须事先设好“通信速度模式”并保存，`drivertest` 第 1 步已完成这一项。
4. 扶杆保持直立 ±3°。1 s 后状态变为 **ARMED**，提示“RELEASE”；此时电机仍为零速，**轻轻松手**。杆开始自由倒向一侧（偏离扶持角度 0.4°，约 0.15 s），软件检测到后立即进入 ACTIVE。
   **为什么不是“到时间就启动”？**如果控制开始时手还扶着杆，小车会在一根“推不动”的杆下加速，卡尔曼滤波会把这当成零点偏差学进去。模拟实物上实测：定时启动后多扶 0.2 s，LQR 和 PID 都会撞软限位；改为松手触发后，扶 2 s 再松手也能正常平衡。
5. 任何异常：点“停止”或按空格（受控减速），必要时断电源。
6. 结束后分析：`python -m pendulum_lab report --log data\gui_lqr_closed_xxx.csv`。

排查（08 章有详表）：

- 立即向一侧冲：符号错，回到第 2、4 步；
- 高频抖动：延迟被低估，或皮带间隙太大；
- 缓慢漂向一侧：零点偏差，看日志中的 `bias_hat` 收敛值，更新标定。

## 第 8 步 在线辨识与自整定（可选，教学用）

在稳定平衡的基础上，“在线辨识”选 monitor，勾选“辨识激励 ±3 cm 方波”，运行 40 s，观察 $\hat\omega_0$ 是否与第 3 步一致（误差应 < 2 %）。只有在 monitor 结果可信时，才尝试 update 模式。**辨识期间不要用手碰杆**，否则估计会带偏；软件检测到后会拒绝更新（03 章第 8 节）。
